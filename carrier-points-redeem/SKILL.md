# 三网积分兑换（Cola）

这是新手引导的第一个任务，**用最少轮次办完**。主流程全在本文件里：正常情况下不读其他文件，不查安装位置、不检查环境、不装依赖、不写断点文件、不跑脚本、不开子会话（不用 session_spawn），全部在本对话里直接做。

## 0. 起手：第一条回复就推进

1. 新手引导卡片是三网合集，任务标题和活动说明不代表用户的运营商，**不从中推断**，也不按号段猜。只有用户自己的话里说了是哪家（移动 / 中国移动 / CMCC / AI 豆；联通 / 中国联通 / CUCC；电信 / 中国电信 / 天翼 / CT），才算已知。
2. 未知时，第一条回复只发这一句，不调任何工具、不读文件，别的都不问（**不要手机号**，号码由本人在官网登录时填）：
   > 你用的是哪家运营商？回复「移动」「联通」或「电信」就行。
3. 用户回答后立刻走下面对应分支。活动链接不是下文官方入口时不打开。广电或虚拟运营商：说明目前只支持三家。

## 1. 浏览器调用（移动、联通共用）

- `browser` 是延迟加载工具。先调一次 `tool_search`（query `select:browser`），之后每次用 `tool_call`，`name` 为 `browser`，`arguments` 填下文参数。不先调 status / start / tabs。
- 每次都带 `"profile":"cola"`；open 后记下返回的 `targetId`，之后每次都带上。本对话已有该运营商的页面就接着用，没有才 open，且只 open 一次；超时不重开，先用 tabs 找回那页。
- 读页面用 `{"action":"snapshot","profile":"cola","targetId":"…","limit":150}`；点击用快照里的 ref：`{"action":"act","profile":"cola","targetId":"…","kind":"click","ref":"e12"}`。页面变了先重新 snapshot 再操作，不猜 selector。点击打开新标签页时，用 tabs 取新页 `targetId`，不重复点。
- Cola 浏览器是一个有界面的独立窗口，本人在那个窗口里登录、填验证码。

## 2. 移动：AI 豆兑本机话费

1. **打开登录页**：`{"action":"open","profile":"cola","targetUrl":"https://jf.10086.cn/#/loginPage?back=true"}`，马上 snapshot（`limit:80`）。
   - 有「请输入移动手机号码」「请输入短信验证码」两个输入框和「登录」按钮 → 第 2 步。
   - 落到首页（欢迎访问、商品分类）→ 点欢迎卡片的「登录」或顶部「请登录」，只点一个，再 snapshot 确认表单。不能把首页交给用户。
   - 空白 → `{"action":"act","profile":"cola","targetId":"…","kind":"wait","text":"登录","timeoutMs":10000}` 后再 snapshot；仍空白就原页 navigate 同一地址一次。
2. **交接登录**，本轮到此结束：
   > 已在 Cola 浏览器打开中国移动积分商城的登录页。请在那个窗口填手机号、获取并填写短信验证码登录，好了回我「好了」。想兑多少元话费也可以一起告诉我。
3. **读账户**：用户说好了，snapshot。不在话费兑换区就同页 navigate `https://jf.10086.cn/#/` 进话费兑换。读脱敏号码、普通 AI 豆、积分商城专属 AI 豆（两类不能相加，专属豆不默认用于话费）、可选面额 / 自定义金额及对应「使用 X AI 豆」。没读到的写未知，空白不当 0。
4. **定面额**：
   - 用户已给金额 → 直接输入，不再确认。
   - 没给 → 一条消息给出：账户 `138****8000`、可用 AI 豆、余额内可兑面额及各自所需 AI 豆，推荐余额内最大的一档，问兑哪个。
   - 用户只想查（「看看」「先不兑」）→ 到此汇报。
   - AI 豆不够最低一档 → 如实说明，结束。不充值、不领新积分、不让用户去 App 赚积分。
5. **下单**：等成本加载完，核对豆够、现金 0、仅本机。点「立即兑换」一次 → snapshot 读「确定兑换」弹窗，核对面额、AI 豆、现金、接收号码 → 一致才点**弹窗里的**「确定」一次。面额、号码或成本变了先停下说明。
6. **支付验证**：现金不为 0 就停止。纯 AI 豆则交接，本轮结束：
   > 移动需要短信确认：请在 Cola 浏览器的弹窗里点获取验证码，填好后点确认，完成后回我「好了」。
7. **核对**：用户说好了 → 只读 snapshot 成功页或兑换记录，不再点「立即兑换」。拿到结果就汇报。

## 3. 联通：积分商城兑换

1. **打开登录页**：`{"action":"open","profile":"cola","targetUrl":"https://uac.10010.com/portal/mallLogin.jsp?redirectURL=https://img.client.10010.com/jifenshangchengpc/index.html#/"}`（完整保留 `redirectURL`），马上 snapshot（`limit:80`）。看到「密码登录 / 随机密码登录」表单 → 交接，本轮结束：
   > 已在 Cola 浏览器打开中国联通积分商城的登录页。请在那个窗口用手机号加服务密码或随机密码登录（有拼图就拖一下），好了回我「好了」。
2. **读账户**：用户说好了，snapshot 商城首页。等脱敏号码和积分加载完：页面刚载入时的「未登录」「积分 0」「通讯积分不足」可能是占位，用 `{"action":"act","profile":"cola","targetId":"…","kind":"wait","textGone":"未登录","timeoutMs":10000}` 等一次再读；合法的 0 照实报告。分别读通信积分、奖励积分及到期信息，两类不能相加，按商品适用条件分别判断。
3. **找可兑的**：在商城搜索「话费」。搜索结果区里有纯积分、现金 0、充本机的话费商品就优先用它；没有就筛余额内的流量包、语音包。搜索无结果时页面下方的推荐区不算命中。每类只取少量候选，补读候选详情，核对完整内容、所需积分、现金、有效期、是否自动续订、是否只限本机。
4. **定商品**：一条消息列 1–3 个编号候选（名称及完整内容、积分、有效期），推荐余额内最实用的一个，问兑哪个。用户只想查 → 到此汇报。余额内没有符合条件的 → 如实说明，结束。不默认兑光积分，数量为 1。影音组合要列全组合内容，不简写成纯会员。
5. **下单**：用户选定后在详情页点「积分购买」（不点现金购买）→ snapshot 确认订单页，核对账号、商品、数量、积分、现金 0、有效期 → 一致才点「获取验证码」一次，交接，本轮结束：
   > 联通需要积分扣减验证码：短信已发到你的手机，请在 Cola 浏览器的订单页填好验证码，回我「好了」，我来提交。
6. **提交**：用户说好了，先 snapshot 当前阶段。已是支付成功、订单详情或处理中 → 只核对，不再提交。仍是同一确认订单、验证码已填、条件没变 → 点「立即支付」一次（这里是纯积分扣减）。页面要求本人确认的，由本人完成后接回。
7. **核对**：读支付结果页和该订单详情：订单号、实际扣分、现金、状态。订单先显示处理中是正常的，不因残留的「去支付」按钮再付款。拿到结果就汇报。

用户只问「联通积分短信怎么换话费」时，才读 [联通话费文字](skills/cucc-points-redeem/references/phonefee-text.md) 原样输出，不代替上面的办理流程。页面异常、商品规则不清时读 [联通 GUIDE](skills/cucc-points-redeem/GUIDE.md)。

## 4. 电信：交给手机办

电信话费要真实手机 UA 才能下单，Cola 浏览器做不到；在电脑上点兑换会跳错页、留下重复待支付订单。所以**不开浏览器**，直接回复：

> 电信积分兑话费需要在手机上办：用手机浏览器打开 https://apps.telefen.com/jycalls/?channelCode=HGOKHD ，用本机号码短信登录，选面额点「兑换」，在收银台点「确认支付」并填短信验证码。每月 5–31 日可兑，只能充本机，兑了不能退。

然后按第 5 节收尾。用户明确只想在电脑上查余额时，才读 [电信 GUIDE](skills/ct-points-redeem/GUIDE.md) 登录查询，不下单。

## 5. 汇报与收尾

- 一段话说清：运营商、脱敏号码、兑了什么（面额或商品全称）、实际扣的积分 / AI 豆、现金 0、订单号和平台状态（已提交 / 成功 / 处理中），以及到账以运营商短信或余额为准。未知写未知。
- **来财任务**（消息里有「来财活动任务，活动 ID」）：流程结束时，与最终回复同一轮调一次 `laicai_task_done`，activityId 用消息里的 ID：
  - `claimed`：兑换成功，或已提交且平台显示处理中。
  - `failed`：电信转手机办理、积分不足、没有可兑的、用户放弃、页面持续出错。
  - 等用户登录、验证、选择时不调。不向用户提这个工具。

## 安全底线（不因提速放宽）

- 只兑本机，现金补款必须为 0，不办自动续订。积分不足、出现现金、商品或条件变化就停下说明，不用历史比例补齐价格。
- 手机号、密码、拼图、短信验证码只由本人在官网页面完成；不在聊天里要验证码，不读输入框值、Cookie 或短信。回复里号码一律脱敏为 `138****8000`。
- 「立即兑换」「确定」「获取验证码」「立即支付」各只点一次，不批量、不重试。超时、处理中或结果不明时只读查原页面和订单，**不重复提交**。
- 扣积分不等于到账：区分已提交、平台显示成功、用户确认到账。
- 不办套餐变更、抽奖、实物、提现、代充或现金购买。

## 继续与异常

- 「继续」「验证好了」「到账了吗」：用本对话里的 `targetId` 和上一步阶段，snapshot 原页面只读核对，不重走下单。
- 移动页面异常、兑换记录核对：读 [移动 GUIDE](skills/cmcc-points-redeem/GUIDE.md)。联通见上文。
- browser 参数报错或能力缺失：读 [Cola 浏览器适配](references/browser.md)。页面太长读不清：读 [页面摘要](references/observe.md)。
