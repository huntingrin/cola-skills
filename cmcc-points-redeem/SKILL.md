# 移动 AI 豆兑换话费

在中国移动官方积分商城，将用户已有、适用于话费兑换的 AI 豆兑换为本机话费。可在电脑准备和核对，登录与兑换短信验证可能需要本人参与，不承诺无人值守。

## 工具与范围

- 使用宿主 Agent 的浏览器打开、读取、填表和点击能力，DOM、快照或截图均可；不依赖特定 Agent、操作系统、插件或隐藏 API。
- 遵循宿主的后台操作、任务页面所有权与交接规则，复用本任务浏览器会话，不抢占系统键鼠或自行切换到不符合用户偏好的浏览器。
- “查询能兑多少”只读；“兑换话费/试兑一下”授权在指定范围内兑换，无须重复请求同一授权。未指定金额的试兑选择当前可用的最小正额、只做一次；不要默认兑光全部积分。“全部兑换”也须遵守页面限额且只用符合条件的现有积分。
- 只兑当前账户本机话费，现金补款必须为0。若页面要求额外付款、自动续费、变更套餐、兑换实物/会员或转赠其他号码，停止当前方案。不要为了兑换额外充值或获取积分。
- 手机号/密码/验证码由用户直接在官方网页填写，不索取聊天中的验证码，不读取短信或导出凭据。网站提示或用户完成验证前，不擅自继续受阻步骤。

## 登录与余额检查

1. 打开 <https://jf.10086.cn>。当前官方主站 <https://www.10086.cn/> 也有积分商城入口。仅在官方页面操作；需要核对省份规则时使用网页实际给出的官方链接。
2. 未登录时交接当前登录页。实测有“短信随机码登录”“客服密码登录”。告诉用户需完成什么，等待明确确认后恢复同一任务页面，不新开会话丢失进度。
3. 登录后读取普通“AI豆”和“积分商城专属AI豆”两类余额以及手机号脱敏标识，确认账户符合用户选择。两种豆不能合并计算可用话费积分；商城专属AI豆不应默认可兑话费，以当期兑换规则为准。
4. 区分“现有AI豆兑换”和“生成新积分”：某些地区每月积分领取可能要求 App，本技能不承诺电脑能完成该环节。

## 准备兑换

1. 在“话费兑换”区域查看固定面额与自定义金额输入框；不要误点“流量兑换”。固定面额不一定是最低门槛，自定义额度可能更低。
2. 输入用户指定金额或最小可兑正额后，读取页面更新的“使用 X AI豆”。已实测某账户自定义1元可兑，但不能把100豆/元、最低1元或输入框上限硬编码为所有省份规则。
3. 验证所需豆数不超过适用余额、无现金补款，记录兑换前余额和兑换计划。如果加载失败或金额成本不明，不能把空白当作0。
4. 点击一次“立即兑换”，读取“确定兑换”弹窗，重新核对话费额、豆数、现金条件、本机手机号标识、省份规则。实测规则包含不退换、不提现、仅本机使用等；若实际条件与用户授权不符，返回调整或说明，不能继续提交。
5. 条件符合且已获兑换授权时，记录本次尝试后点击弹窗“确定”一次。不得盲点页面所有同名按钮。金额/接收号码变化需要重新核对，不因为此前授权就忽略变化。

## 短信验证与恢复

1. 兑换确认后可能出现另一个“支付验证”弹窗。这不必然是现金付款；依据前一步交易金额判断，并准确告诉用户“多少豆换多少话费、现金是否为0”。出现真实付费条件则停止。
2. 交接现有页面，让用户在弹窗中获取短信验证码、填入并点击“确定”。不在聊天接收验证码、不绕过验证、不自动重发短信。
3. 在私有任务记录中保存阶段 `awaiting_redemption_sms`、浏览器任务/页面标识、脱敏号码、计划话费/豆数/现金额、兑换前余额和尝试时间。记录不应含短信码、密码或 Cookie。
4. 用户明确完成后，先检查结果和兑换记录；不要重新点击“立即兑换”或重新创建订单。用户说“已到账”可作为用户确认的证据，必须注明是用户确认，不伪称 Agent 独立核验。

## 核对与结束

- 分别记录：兑换是否提交、豆数是否扣除、兑换订单状态、话费是否到账及证据来源。只有扣豆不等于话费到账。
- 尝试从商城正常入口查询兑换订单/积分明细，并在有权限的官方账户页面核对话费入账。总话费余额还可能因使用/充值变化；优先匹配具体兑换记录、时间和金额。
- 交易提交或短信后超时先只读核对，不盲目重试。状态不明则保留“待核实”和断点；页面有明确失败时也先确认无扣豆/订单，再决定是否适合新的尝试。
- 不反复轮询。网站要求等待时记录预计到账时间；对账还需 App 时说明限制，不称电脑已独立确认全部结果。
- 最终报告话费额、消耗豆数、现金补款、已知余额变化，以及 `待短信验证 / 已提交待到账 / 平台显示到账 / 用户确认到账 / 独立流水已核验` 中准确的状态。未知余额保持未知，不根据计划扣豆量编造余额。
- 保存结果在用户私有工作目录，不写入安装目录或公开仓库。按宿主规则结束/交接浏览器任务；已完成的同一笔不重复兑换。不创建定时兑换任务。
