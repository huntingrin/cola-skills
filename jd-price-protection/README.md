# 京东价保 Skill

让具备浏览器操作能力的 AI Agent 检查已有京东订单，申请符合条件的价保，并核对退款进度。

## 安装与使用

```sh
git clone https://github.com/huntingrin/jd-price-protection.git
```

把仓库作为 `jd-price-protection` 文件夹放入 Agent 支持的技能目录，具体路径以宿主文档为准。没有 Skill 加载机制时，可让 Agent 直接读取 [SKILL.md](SKILL.md)。

示例指令：

> 使用 jd-price-protection，检查我的京东订单，对符合条件的订单申请价保，汇总退款金额和到账状态。

只检查可说：“检查可价保订单，先不提交申请。”

## 运行要求

- Agent 能打开网页、读取页面并点击控件；仅文本聊天不能实际执行。
- 用户在 Agent 使用的浏览器中登录自己的京东账户，验证由本人处理。
- 无特定浏览器、模型、操作系统、Node.js 或 API 依赖；遵循宿主工具权限和用户的后台操作偏好。

技能覆盖资格检查、逐商品申请、退款详情核对和中断恢复。不购买商品、不退货、不提现、不设置定时任务。

## 已验证与限制

- 2026-10-12：在电脑网页与 Ego 浏览器中实测完成一次价保申请，平台退款详情显示成功返至钱包余额。
- 2026-10-16：在 Ego 浏览器中复跑完整链路（判定资格 → 提交 → 申请记录 → 退款详情），一次点击申请成功，退款详情显示返至钱包余额、状态已退款成功。个人钱包流水未独立核验，因此技能明确区分“平台退款成功”和“实际到账”。
- 未逐一测试所有 Agent、所有操作系统或所有订单品类。
- 申请页只覆盖最近三个月订单，且没有分页；更早的订单只能用订单号搜索框定位。
- 页面先渲染商品行、后异步补全限制说明和按钮状态，判定前必须等稳定，否则价格和资格都可能读错。
- 重新加载后，已申请成功商品的按钮会恢复成可点击状态，防重只能靠行内追加的成功说明文字，不能靠按钮外观。

平台可能异步补充过期说明，存在申请按钮不代表一定符合条件。奖励金额不固定，支持周期和返还方式以具体订单为准。
