# Changelog

## 2.3.0

- 改成直接发技能包自带的两张码：不问平台、不问用途、不问链接、不读项目配置。
- 新增 `assets/` 两张固定 PNG；装好即可用，空项目也能发。
- 删除 `resolve_config.mjs` 和「红包配置.json」流程，避免再把「找不到旧链接」当成缺链接。
- 保留 `check_link.mjs` / `make_qr.mjs`，只在用户明确说「换链接 / 换码」时使用。
- 明确码随技能包分发；换链接必须重新生成 `assets/` 里的 PNG。

## 2.2.1

- 新增 `scripts/resolve_config.mjs`，按归一化项目名查找配置。
- 固定项目名支持 `淘宝闪购 · 滴滴红包二维码` / `淘宝闪购滴滴红包码` / `淘宝闪购·滴滴红包码` 等变体。
- 删除开头与 2.2.0 流程冲突的「先问平台和用途」。

## 2.2.0

- 默认一次给淘宝闪购 + 滴滴两张码，不再让用户选平台。
- 不再先问「自己扫还是发群」；默认自己扫文案，末尾给发群替换句。
- 只缺一条链接时，只问缺的那条一次；两条都没有才问两条。
- 用户明确说「只要淘宝闪购 / 只要滴滴」时才只做一个。

## 2.1.0

- 「自己扫」也生成二维码，不再把用户打发去 App；文案与发群分开。
- 当前项目没有链接时，只查固定项目「淘宝闪购 · 滴滴红包二维码」/「淘宝闪购滴滴红包码」，不扫描所有项目。
- 平台别名归一：淘宝闪购 / 饿了么；滴滴 / 滴滴出行 / 滴滴打车。
- `check_link.mjs` 支持 meta refresh 短链（如滴滴券包短链），并识别 `source_id`/`channel_id` 等归因参数。
- 明确「自己扫」和「发群」两套交付文案。

## 2.0.0

- 首次加载/空请求时主动引导，不再等用户先给链接。
- 小白流程：先问平台，再问自己领还是发群，最后才问链接；一次只问一件事。
- 用户可见文案不再出现 `sid`、`utm`、`scene`、`spm`、`qrcode_url` 等术语。
- 新增无依赖二维码生成脚本 `scripts/make_qr.mjs`（PNG，带 `VERIFY: png-ok` 容器校验）。
- 新增无登录链接检查脚本 `scripts/check_link.mjs`。
- 明确 Cola 交付：保存到项目 `交付物/`，用 `MEDIA:` 绝对路径发送。
- 「再来一张」直接复用现有二维码，不重复制码、不新建 `-2` 文件。
- 不声称「我扫过」；没有本地解码器就如实说明未做扫码验证。

## 1.2.1

- 修复二维码中文/非 ASCII 字符编码，超长链接明确报错。
- 修复 UTF-8 静默乱码与超长链接裸栈。
