# 淘宝闪购 / 滴滴红包码

默认只做一件事：把技能包自带的两张码发给用户，告诉他扫这两张。不问平台、不问用途、不问链接。

## 0. 默认流程（每次都一样）

1. 定位技能目录（`SKILL.md` 所在目录），找两张图：
   - `assets/淘宝闪购-红包二维码.png`
   - `assets/滴滴-红包二维码.png`

   ```bash
   SKILL_DIR="$(dirname "<SKILL.md 的绝对路径>")"
   ls -l "$SKILL_DIR/assets"
   ```

2. 两个文件都存在且大小 > 0：直接交付。不要读项目配置、不要联网检查、不要问任何问题。
3. 按固定顺序交付：淘宝闪购 → 滴滴。每条是「平台名 + 一句自己扫文案 + 单独一行 MEDIA」：

**淘宝闪购**

> 扫码打开淘宝闪购红包活动，按页面提示登录领取。

MEDIA: <SKILL_DIR>/assets/淘宝闪购-红包二维码.png

**滴滴**

> 扫码打开滴滴红包活动，按页面提示登录领取。

MEDIA: <SKILL_DIR>/assets/滴滴-红包二维码.png

`<SKILL_DIR>` 换成 `SKILL.md` 所在的绝对目录，不要原样输出占位符；`MEDIA:` 必须单独一行。

4. 用户明确说「发群」：只换文案，不换码：

   > 扫码领取淘宝闪购红包，具体权益以活动页面为准。
   > 扫码领取滴滴红包，具体权益以活动页面为准。

   末尾补一句「发群只发图片和这句话」。
5. 用户说「再来一张」：原样再发这两张，不重新生成、不新建文件。
6. 用户明确只要一个平台：只发那张；否则默认两张都给。

## 1. 图片缺失怎么办

只有 `assets/` 里缺图或文件读不出来时，才说：

> 技能包里的二维码没装好，我这边发不出来；重新安装一次技能包就行。

不要改问用户要链接，不要说「缺链接」。链接已经编在码里。

## 2. 边界

- 不登录用户账号、不代领、不碰验证码；验证码只有本人能填。
- 不承诺具体金额/折扣/到账；以活动页面为准。
- 默认只发给当前请求者，不主动发群。
- 不说「我扫过 / 我验证过二维码」，除非真的用本地解码器读过。
- 推广链接已经在二维码里；不要把链接、二维码、账号信息写进全局记忆或书签。

## 3. 维护（仅当用户明确说「换链接 / 换码」）

默认流程不读这一节。用户要换活动时：

1. 让用户提供新的完整推广链接（淘宝闪购 / 滴滴各一条），参数别删。
2. 用 `scripts/check_link.mjs` 做一次无登录连通性检查；有 `sid=123456` 占位符就停下来让用户换渠道号。
3. 用 `scripts/make_qr.mjs` 生成新 PNG，覆盖 `assets/` 下同名文件；先备份旧图。
4. 有本地解码器就解回链接核对；没有就如实说「文件已生成，未做扫码验证」。
5. 不要把新链接写进技能目录的文本文件；只保留 PNG。

## 4. 交付前检查

- [ ] `assets/` 里两张图都在、大小 > 0？
- [ ] 两个 `MEDIA:` 都是绝对路径、各自单独一行？
- [ ] 有没有问平台、用途、链接？都不要问。
- [ ] 默认自己扫文案；用户说发群才换句？
