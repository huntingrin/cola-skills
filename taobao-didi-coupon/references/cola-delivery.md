# Cola 交付规则

本技能在 Cola（`/Users/tangguorong/Project/cola_main`）里运行时，最终文件必须让 Cola 真正送到用户手里。

## 1. 文件用 MEDIA 行交付

Cola 只把回复里的 `MEDIA: /绝对路径` 行解析成文件卡片 / 内联图片。Markdown 链接 `![二维码](/path.png)` 只是提及，用户不一定能保存。

正确：

```text
扫码领取淘宝闪购红包，具体权益以活动页面为准。

MEDIA: /Users/me/cola/outputs/淘宝闪购-红包二维码.png
```

错误：

```text
二维码在：/Users/me/.../qrcode.png
```

（只有路径、没有 `MEDIA:`，Cola 不会把文件送到对话里。）

规则：

- `MEDIA:` 必须单独一行，后面跟绝对路径，不要加引号、不要加说明。
- 一个文件一行；多平台就多行。
- 文件必须真实存在、大小 > 0；发送前用 `ls -l` 检查。

## 2. 保存位置

- 用当前项目工作目录（`pwd`）下的 `交付物/` 子目录；没有就创建。
- 如果 `pwd` 是 `outputs/` 或 Inbox 根目录，不是具体项目：先找/建固定名项目「淘宝闪购 · 滴滴红包二维码」，再进项目目录，不要在根目录散放文件。
- 不要写到 `~/.cola/skills/`、共享技能目录或 `/tmp`。
- 文件名用可读的中文：`淘宝闪购-红包二维码.png`、`滴滴-红包二维码.png`；同一活动多张时加日期或序号，避免覆盖。
- 二维码文件是用户交付物，不要放进技能包、不要提交到仓库。

## 3. 一条回复的结构

先给用户能直接复制/保存的两样：

```text
扫码领取{平台}红包，具体权益以活动页面为准。

MEDIA: /abs/path/交付物/{平台}-红包二维码.png
```

再给操作者说明，并标明「不要发群」：

```text
【下面给你看，不要发群】
- 长按图片保存；发群时只发图片和上面那句话。
- 扫码后如果让你登录，按页面提示登录；验证码只有本人能填。
- 活动规则/券面以页面为准；不承诺具体金额。
```

不要把 JSON、`sid`、`utm`、工具报错、文件路径说明发进群。

## 4. 项目配置

- 配置放在项目工作目录的 `红包配置.json`，和交付物同一个项目。
- 推广链接属于项目配置，不要写进全局记忆/书签；不要把链接、二维码、账号信息写进共享技能目录。
- 技能目录是只读的共享资源，不要把用户链接、二维码、账号信息写进去。
- 如果项目工作目录每次都是新的临时目录，配置会丢；告诉用户「这个项目要固定保存，下次才不用再发链接」。
- 细节见 [项目配置](project-setup.md)。

## 5. 发送前检查

- [ ] `pwd` 是项目目录，不是技能目录。
- [ ] `交付物/` 存在。
- [ ] 二维码文件存在且大小 > 0。
- [ ] `MEDIA:` 行是绝对路径、单独一行。
- [ ] 发群句只有一句，没有括号备注、没有操作步骤。
- [ ] 操作者说明和发群内容分开。
- [ ] 没有把用户链接/二维码写进技能目录。
