# 首次引导（默认两张码）

只在首次使用、空请求、用户说「怎么用 / 开始 / 帮我领红包」时读。目标是**直接给两张码**，不要让用户选平台。

## 1. 加载后先做

默认两个平台都要：**淘宝闪购 + 滴滴**。不要问「要哪个平台」，也不要先问「自己扫还是发群」。

先查两个地方：

1. 当前项目的 `红包配置.json`
2. 固定项目「淘宝闪购 · 滴滴红包二维码」或「淘宝闪购滴滴红包码」的 `红包配置.json`

然后分三种情况：

### A. 两条链接都有

> 两张码给你：淘宝闪购 + 滴滴。我先检查链接，马上做。

直接检查 → 生成两张码 → 交付。不要停下来问问题。

### B. 只有一条

> 我先给你有的这张；另一条链接发我一下，我一起补齐。

先交付已有的那张，再只问一次缺的那条。不要连续追问。

### C. 两条都没有

> 我需要淘宝闪购和滴滴各一条活动链接。有就整条发我，没有我带你找。
> 打开推广后台 → 推广/活动 → 选平台 → 点「我要推广」→ 复制整条链接；参数别删。

拿到后两张一起做，不要只做一张。

## 2. 链接检查

对每条链接跑：

```bash
node "$SKILL_DIR/scripts/check_link.mjs" "<链接>"
```

- `ok: true`：继续做码。
- `sid_placeholder`：让用户换渠道号，不要发。
- `login_page` / `loginWrapper`：正常，扫码后要登录。
- `metaRedirect`：短链先跳一次，正常。
- `http_error` / `network_error`：404/410 大概率死链；403/429/超时可能是风控，先让用户手机扫一下，别直接判死。

`ok` 只代表能打开，不代表券还能领、佣金能到账。

## 3. 交付（默认两张一起给）

默认用「自己扫」文案；用户明确说发群时，换成发群句。

**淘宝闪购**

> 扫码打开淘宝闪购红包活动，按页面提示登录领取。

MEDIA: /abs/path/交付物/淘宝闪购-红包二维码.png

**滴滴**

> 扫码打开滴滴红包活动，按页面提示登录领取。

MEDIA: /abs/path/交付物/滴滴-红包二维码.png

末尾补一句：

> 要发群就把文案换成「扫码领取{平台}红包，具体权益以活动页面为准」；自己扫就用原来的。

再给操作者说明：

> 【下面给你看，不要发群】
> 长按图片保存，两张都存，别混。
> 第一次用某张码，建议自己先扫一下，确认能打开活动页再发群/自己领。
> 扫码后如果让你登录，按页面提示登录；验证码只有本人能填。
> 具体券额以活动页为准，我不打包票。

两张都要交付，不要只给一张。

## 4. 用户明确说「只要淘宝闪购 / 只要滴滴」

只做他点名的那个；不要反问「另一个要不要」。默认场景仍然是两张都给。

## 5. 用户说「发群」

平台仍然默认两张都给；文案换成发群句，并在末尾写「发群时只发图片和那句话」。

## 6. 用户说「再来一张」

如果两条配置的 `qrcode_url` 和 `url` 相同、二维码文件都在，直接把两张现有图片再发一次；不要重新生成、不要新建 `-2` 文件。

## 7. 示例对话

**例 1：空请求，两条链接都有**

用户：`/taobao-didi-coupon`

助手：两张码给你：淘宝闪购 + 滴滴。我先检查链接，马上做。→ 两张码 + 两段文案 + 两个 `MEDIA:`。

**例 2：空请求，没有链接**

用户：`/taobao-didi-coupon`

助手：我需要淘宝闪购和滴滴各一条活动链接。有就整条发我；没有我带你找。→ 拿到两条后两张一起做。

**例 3：只有淘宝闪购链接**

用户：[淘宝闪购链接]

助手：先给你淘宝闪购这张；滴滴的链接发我一下，我一起补齐。→ 淘宝闪购码 + 等滴滴链接。

**例 4：发群**

用户：发群

助手：好，两张都按发群文案来。→ 两张码 + 两句发群句 + 「只发图片和这句话」。

**例 5：再来一张**

用户：再来一张

助手：好，两张都用你上次存的链接。→ 直接复用现有两张码，不重新生成。

## 8. 语气要求

- 用「你 / 我」，短句，先说结论。
- 不要问「淘宝闪购还是滴滴」；默认两张。
- 不要问「自己扫还是发群」；默认自己扫，末尾给发群替换句。
- 不主动说 `sid`、`utm`、`scene`、`spm`、`qrcode_url`、`JSON`、`工作目录`、`归因` 这些词；用户问再解释。
- 不承诺「一定能领到」「最高 XX 元」；说「以活动页面为准」。
- 不说「我扫过 / 我验证过二维码」，除非真的用本地解码器读过；`VERIFY: png-ok` 只代表 PNG 写对了。不要用 `vision_analyze` 读二维码，它会猜。
- 不把工具报错原文贴给用户；翻译成「链接打不开 / 二维码没生成 / 需要登录」。
