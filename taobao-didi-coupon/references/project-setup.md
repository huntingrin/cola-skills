# 项目配置与稳定复用

仅在首次保存链接、明确更换默认、修复配置或保存二维码引用时使用；配置正常的领取直接走主流程。

Cola 下优先用当前项目目录（`pwd`）；如果 `pwd` 是 `outputs/` 或 Inbox 根目录，先找固定名项目「淘宝闪购 · 滴滴红包二维码」，再进项目目录；找不到就先在本次会话工作，拿到真实链接并完成交付后再建，不要提前建空项目。配置和 `交付物/` 都放项目里。链接检查可用 `node "$SKILL_DIR/scripts/check_link.mjs" "<完整链接>"`，它只做无登录的连通性检查，不验券、不登录。`SKILL_DIR` 是 `SKILL.md` 所在目录，不要假设当前目录就是技能目录。

项目名建议固定为「淘宝闪购 · 滴滴红包二维码」；已有就复用，不要每次新建重复项目。已有名字接近的项目（如「淘宝闪购滴滴红包码」「淘宝闪购·滴滴红包码」「淘宝闪购-滴滴红包二维码」）也优先复用，不要为了统一名字再建第二个。

查找用脚本，不要按字面名字猜：

```bash
SKILL_DIR="$(dirname "<SKILL.md 的绝对路径>")"
node "$SKILL_DIR/scripts/resolve_config.mjs" --current "$PWD"
```

它只查当前项目、Cola 项目登记和 `outputs/*` 里名字像红包项目的目录；返回 `usable`、`missing`、每个平台的 `sourceDir`。名字匹配会去掉空格、`·`、`-`、括号再比，不要求字面完全相等。

## 最小结构

- 调用会话工作目录即本次项目工作区；其中「红包配置.json」是 UTF-8 JSON 对象，顶层为按平台的字典映射。
- 当前项目没有配置时，只允许再查固定项目的名字变体（`淘宝闪购 · 滴滴红包二维码` / `淘宝闪购滴滴红包码` / `淘宝闪购·滴滴红包码` / `淘宝闪购-滴滴红包二维码`）；不要扫描用户所有项目，也不要按字面名字严格要求相等。
- 键使用中文平台名，如「淘宝闪购」「滴滴出行」；别名归一：`淘宝闪购` / `饿了么` 视为同一个，`滴滴` / `滴滴出行` / `滴滴打车` 视为同一个。每项是对象，必需字段 `url` 为用户明确提供或确认的完整推广链接。
- 可选字段 `qrcode` 为相对调用工作目录的本地二维码文件路径，例如 `交付物/滴滴-红包二维码.png`。
- 可选字段 `qrcode_url` 为生成或核实该二维码时记录的完整原链接，与 `qrcode` 成对保存；不能只因配置有 `url` 就补写未核实的对应记录。
- 可选字段 `text` 为人工文案，仅在已确认适用于当前平台、链接及权益时复用；不得悄悄覆盖。
- 不预制空配置，不写占位 URL、历史示例、账号或凭证。不把配置和用户二维码装进技能包。

## 保存规则

1. 读取已有配置再修改。不存在时，在拿到真实链接并完成当次交付后建立；首次只有会话确认链接时，也可保存已明确确认的稳定引用。
2. 解析失败、目标项格式错误或文件内容与预期不符时，保留原文件，向用户说明需修复；不清空、不假定缺失后覆盖。当前明确链接仍可用于当次交付。
3. 新平台仅添加该项；已有平台只改获准更新的 `url` / `qrcode` / `qrcode_url`，合并保留 `text`、其它字段和其它平台。
4. 本次不同链接不悄悄改默认，也不把本次二维码挂到旧默认 URL 下。明确更换默认时更新目标 URL：新码已核实则同步更新 `qrcode` 与 `qrcode_url`；新码未就绪则仅清理失配的这两个二维码引用字段，保留其它数据。
5. 相同默认 URL 的新码核实后同步保存 `qrcode` 与 `qrcode_url`；无二维码时只保存 URL，不写不存在的路径或伪造对应记录。路径保持在项目工作区内（Cola 下放在 `交付物/`），不指向共享技能目录或其它项目。
6. 将合并后的 JSON 写入同目录独立临时文件并检查，再原子替换已读过的配置；二维码的路径与原链接在同一次写入中更新，避免半写或失配。用户项目中的非本技能文件不擅自覆盖。

## 复用核验

常用路径只比较目标平台的 `qrcode_url` 与本次所选完整 URL、检查 `qrcode` 文件存在；满足即直接复用，不解码、不看图、不联网。用户说「再来一张」时也走这条：直接把现有文件再交付一次，不重复制码、不新建 `-2` 文件。已明确过期或失效的入口仍不能复用。
仅旧配置缺 `qrcode_url`、记录不一致或文件缺失时核验/制码。旧码经现成能力核实与当前原链接一致后，成对保存对应记录；不能确认则不复用，不凭路径或文件名猜测。
没有可用入口时先查固定项目；仍没有，再只问一次该平台现成推广链接，不登录或转链寻找替代品。新码持久存入项目内 `交付物/` 专用子目录；文件名冲突时用新名字。

## 生成二维码

优先使用随技能带的脚本（不装依赖、不联网、不用图像模型）：

```bash
SKILL_DIR="$(dirname "<SKILL.md 的绝对路径>")"
node "$SKILL_DIR/scripts/make_qr.mjs" "<完整链接>" "<项目目录>/交付物/<平台>-红包二维码.png"
```

脚本路径相对本技能 `SKILL.md` 所在目录解析。脚本会打印 `QR: <绝对路径>`；把这个路径用 `MEDIA:` 单独一行交付。生成后确认文件存在、大小 > 0，再写 `qrcode` / `qrcode_url`。脚本不可用时给真实原链接，并如实说明「二维码未生成」。
